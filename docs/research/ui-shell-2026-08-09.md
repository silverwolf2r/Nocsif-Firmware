# UI shell plan — menu-first on-watch UI (design-spec foundation)

Sourced implementation plan → phased build. As of **2026-08-09**. Read this before coding any UI-shell
phase. Neutral device-class framing per `docs/RESUME.md` (Wording convention). This is a **new milestone**
(the first non-M4 UI work); it implements the foundation of `docs/design/ui-design-spec-2026-08-08.md`
(visual source of truth: `docs/design/ui-mockup.html`) on top of the existing M3 `esp_lvgl_port` setup in
`firmware/src/ui.c`, and prepares the screen slots the M5+ capability suites will fill.

## Decision (pending user review — do not code until confirmed)
Replace the flat M3/M4 demo screen in `ui.c` (one `lv_screen_active()` with three buttons) with the design
spec's **menu-first navigation shell**: a boot screen, a Home list of capability categories, per-category
submenus, and action screens, over a **static** star/orrery background, drawn in the spec's grayscale +
serif-over-mono identity, with the **real** clock (RTC) and battery (PMU) bound in. Un-built categories are
present-but-disabled. Delivered as **five independently-flashable phases**, front-loading the two unknowns
the design spec itself flags as risky (embedded-font flash cost + the render-once background/power model) so
each is proven in isolation before the whole screen system depends on it.

| # | Phase | Proves (the unknown it retires) | Effort |
|---|-------|--------------------------------|--------|
| **P1** | Embedded serif+mono fonts + color-token `lv_style_t` set | font pipeline + **flash budget** + per-widget serif selection, isolated | ~1 d |
| **P2** | Static orrery/star background + rounded-corner masks + screen-compositing model | **render-once / no per-frame repaint** + transparent screens over a persistent bottom layer | ~1–1.5 d |
| **P3** | Navigation shell: Home → submenu → action stack, header, slide+fade, list rows, stubs | the menu-first structure + directional transition + disabled stubs | ~2–3 d |
| **P4** | Real bindings: RTC clock + battery %, and migrate the M4 USB controls into the USB action screen | live header data + **M4 USB/HID not regressed** through the new UI | ~1–1.5 d |
| **P5** | Boot screen (engraved star + wordmark + real bring-up log → fade to Home) + motion helpers | boot reveal driven by real init results; reusable sweep/handoff motion; reduced-motion flag | ~1 d |

Rejected: **build-the-whole-UI-in-one-pass** (stacks the font-cost unknown, the background/power unknown,
the nav rewrite, and the new RTC/PMU bindings into one un-bisectable flash — the same anti-pattern the M4
plan rejected). Each phase below ends in a flashable image whose one new thing is verifiable on COM7 before
the next starts.

## The unknowns that shaped the phase order
1. **Embedded fonts are the identity, and their cost/pipeline is the first real unknown.** The spec's whole
   character is *serif titles over mono data* (§3) — the current build has only Montserrat 14. We must run the
   `lv_font_conv` pipeline for **seven faces** (serif 30 boot, serif 21 titles, serif 13 italic captions; mono
   11/13/14/15) at 4 bpp, register them as `lv_font_t`, and select them **per widget** (LVGL falls back to the
   Montserrat default otherwise — spec §3). *Honest sizing:* the factory app partition is **4 MB** with the P4
   firmware at ~0.7 MB, so ~3.3 MB is free and fonts (est. ~90–140 KB total, in flash `.rodata`, not RAM) are
   **not** a fit risk — the real risk is pipeline correctness (glyph ranges incl. the `°·✦–` symbols; picking
   the serif face; that per-widget selection actually overrides the default) and the **measured** delta. P1
   retires it before any screen depends on a font handle.
2. **The background must be static — "render once; must not repaint per frame" (spec §6/§8) — and that dictates
   the whole screen-compositing model.** The clean LVGL v9 answer is the per-display **bottom layer**
   (`lv_layer_bottom()`): draw the orrery into it once, make every screen's background **transparent**, and the
   orrery shows through and persists across screen swaps without being re-rendered. This combination
   (transparent screens + persistent bottom layer + `lv_scr_load_anim`, all through the CO5300 2-px-rounder
   partial-flush path) is unproven on this stack, so P2 validates it behind the existing demo before P3 builds
   eight screens on the assumption. It also settles the corner-mask approach for the physically rounded glass.
3. **Two brand-new hardware bindings (RTC + battery gauge) don't exist yet.** `power.c` only *gates* rails — it
   never reads the fuel gauge — and there is **no RTC driver at all**. Both are additive and low-risk, so they
   come after the visual shell is standing (P4), not before; but they are new I²C device drivers, not just UI.

## Screen-architecture decision (load-bearing for P2/P3)
**Recommendation: separate `lv_screen`s loaded with `lv_scr_load_anim(scr, LV_SCR_LOAD_ANIM_MOVE_LEFT/RIGHT,
240, 0, /*auto_del=*/false)`; a C nav-stack array holds the pushed screens.** Forward = MOVE_LEFT, back =
MOVE_RIGHT (spec §5, ~240 ms directional slide+fade). Each screen's root has a **transparent** background
(`lv_obj_set_style_bg_opa(scr, LV_OPA_TRANSP, 0)`) so the P2 bottom-layer orrery shows through; the shared
header (back arrow + serif title + clock + battery + dashed rule) is produced by one `build_header()` helper
per screen so styling/bindings live in one place.

- **Alternative considered — single screen + swappable container views** (the mockup's literal DOM approach:
  one `.app`, N `.view` children toggled active, animated with `translate_x`+opacity). Rejected as the default
  because it means hand-rolling the slide animation with `lv_anim` and managing z-order/pointer-enable per view;
  `lv_scr_load_anim` gives the exact directional slide+fade for free. Keep it as the fallback if the
  transparent-screen-over-bottom-layer compositing misbehaves in P2.
- **Back stack:** `stack[]` of `lv_obj_t*` screen roots (mirrors the mockup's `stack=['home',…]`). Home is index
  0 and has no back arrow. Push builds/loads a screen; pop loads the parent with MOVE_RIGHT. `auto_del=false`
  keeps screens alive so back is instant and state (e.g. a running scan) survives; a later refinement can rebuild
  leaf action screens on entry if memory pressure ever shows (boot heap is ~8.5 MB, so caching all ~8 screens is
  fine).
- **Compositing honesty:** with transparent screens the bottom-layer orrery is re-blended only inside whatever
  region a top widget invalidates (e.g. the 1 Hz clock → a tiny header rect). During a `lv_scr_load_anim` the
  full screen area animates for ~240 ms (both screens drawn over the orrery) — that is the one intended motion,
  not idle repaint. After it settles there is **no** background repaint. This satisfies spec §8's "no
  ambient/idle animation."

## Phases in detail

### P1 — Embedded fonts (serif + mono) + color-token style set
**Goal / proves:** the `lv_font_conv` → `lv_font_t` → per-widget-selection pipeline works on-panel, the serif
face is chosen, and the **flash delta is measured** and confirmed to leave ample headroom — all before any
screen structure depends on a font handle.
- **Font production (`firmware/src/fonts/`, generated `.c`):** convert with `lv_font_conv` (npm) or the online
  LVGL converter, **4 bpp**, base range **0x20–0x7E** plus the extra glyphs the spec uses: `°` (U+00B0), `·`
  (U+00B7), `–` (U+2013), `✦` (U+2726, the engraved-star text glyph if used inline). Generate **only the sizes
  used** (spec §3): serif **30** (boot wordmark — can subset to `NOCSIF` letters only, it renders nothing else),
  serif **21** regular (titles), serif **13 italic** (captions); mono **11 / 13 / 14 / 15**. Name them
  `nocsif_serif_30`, `nocsif_serif_21`, `nocsif_serif_13i`, `nocsif_mono_11/13/14/15`; add the `.c` files to
  `SRCS` in `src/CMakeLists.txt`; declare `extern const lv_font_t …;` in a new `ui_theme.h`.
- **Serif face:** ship **Recia** or **Boska** (Fontshare, free; spec §3/§12). Convert both at 21 px, render a
  title on-device, keep whichever is cleaner at 21 px on-panel. Record the choice in the RESUME entry.
- **Color tokens (`ui_theme.c/.h`, new):** the spec §2 palette as a shared set — either named `lv_color_t`
  constants (`NOCSIF_VOID 0x070708 … NOCSIF_VIOLET 0x655578`) plus a few reusable `lv_style_t` (title, row-name,
  row-tag, caption, dashed-rule) so a later theme swap (violet→gold, spec §12) is one place. Define colors with
  `lv_color_hex(0xRRGGBB)` **normally** — the panel's BGR handling already lives in the M3 flush config; do **not**
  hand-swap bytes (spec §2, M3 finding).
- **Land it visibly:** temporarily re-skin the existing M3 demo — set the button label to serif 21, add a mono
  line — so the phase produces a flashable image that *shows* serif-over-mono in NocSif colors.
- **Verify (COM7 + eyeball):** titles render in the serif face (not Montserrat); mono lines are tabular; the
  `°·–` glyphs draw; boot-log build output + a `size`/`idf.py size` (or the PlatformIO build summary) show the
  app-image growth, and it is well under the 4 MB partition. Confirm generated `sdkconfig` still has
  `CONFIG_LV_COLOR_DEPTH=24` (M3 gotcha).
- **Risks:** wrong/omitted glyph range → missing symbols render as boxes; forgetting `lv_obj_set_style_text_font`
  on a title → silent Montserrat fallback (spec §3); converting at the wrong bpp inflates flash; the online
  converter's kerning tables differ from `lv_font_conv` — pick one tool and keep it.

### P2 — Static orrery/star background + corner masks + compositing model
**Goal / proves:** the orrery renders **once** to the bottom layer and never repaints per frame; screens with
transparent backgrounds composite over it correctly through the CO5300 partial-flush + 2-px rounder path; the
physically rounded glass corners are masked.
- **Background (`ui_background.c`, new):** draw into `lv_layer_bottom()` **once** at init. Cleanest for dashed
  concentric rings + scattered dots + engraved stars is an **`lv_canvas`** sized 410×502 in **PSRAM** (M1
  framebuffer precedent) rendered once with `lv_draw_arc` (the two orrery ring clusters bleeding off top-right
  `(356,56)` and bottom-left `(44,476)` — radii/opacity/dash from mockup lines 143–159), small filled circles
  (the ~15 gray star dots + 2 violet bodies), and the engraved-star image (below) for the 4 celestial stars
  (one violet, per §6). Alternative: a pre-converted static image if canvas draw-once proves fiddly. Colors:
  rings `#3C3C44` ~0.2 opa, dots `#B6B6BD` 0.2–0.4, one star `#655578`. Add the canvas/image as a child of
  `lv_layer_bottom()`; **never invalidate it again**.
- **Engraved-star asset:** convert the mockup's `#i-star` SVG (line 128 — a 4-point star, thin outline, concave
  sides) to an **A8 (alpha-only) LVGL image** at ~26–30 px so it can be recolored (`lv_obj_set_style_image_recolor`
  + `_opa`) gray or violet from one asset. This asset is reused by the boot screen (P5) and a System→About glyph,
  so it's produced here first.
- **Corner masks (spec §4):** put four opaque `NOCSIF_VOID` rounded-corner masks (~40 px radius) on
  `lv_layer_top()` so the full-bleed orrery can't bleed under the glass curve. Simplest robust form: four small
  corner images with an inner rounded cutout, or four `lv_obj` wedges; fallback is simply keeping background
  marks out of the ~40 px corner arcs. Content already lives within the 24 px safe inset, so only the background
  needs masking. Do **not** round the framebuffer (spec §4).
- **Prove render-once / power:** behind the still-present demo, confirm via the flush path (temporary log count
  of flush callbacks, or watching that no periodic invalidation occurs when idle) that the background does **not**
  repaint when nothing changes; only widget-driven regions flush. This is the make-or-break for the whole
  approach and is why it precedes P3.
- **Verify (eyeball + COM7):** orrery + stars visible behind the demo; corners clean under the glass; idle =
  no background flushes; a forced widget change flushes only its region. Colors read as the near-black grayscale
  ground with the single violet star.
- **Risks:** transparent-screen + bottom-layer compositing not supported cleanly by esp_lvgl_port's flush model
  (→ fall back to per-screen baked background or the container-view architecture); a PSRAM canvas needing a
  bounce buffer for the SPI flush (M3 kept draw buffers in internal RAM — the *background* canvas is only
  composited, not DMA'd as a draw buffer, but validate); over-drawing arcs each frame by accident (must draw
  once). If canvas-in-PSRAM is troublesome, pre-render the orrery to a flash image.

### P3 — Navigation shell: Home → submenu → action, header, transitions, stubs
**Goal / proves:** the menu-first stack and the directional slide+fade, with real list rows, icons, tags, and
the dashed header — the structural core of the spec.
- **Icons (`firmware/src/icons/`, generated):** convert the mockup's SVG symbols (lines 113–128: wifi, nfc, ble,
  usb, sys, scan, monitor, ap, portal, cap, drive, lock, open, chevron, back, star) to **A8 LVGL images** at
  their on-screen sizes (module icons ~21 px, chevron/back ~14–17 px), recolored per state via
  `lv_obj_set_style_image_recolor(_opa)` (steel at rest → violet on press; §6/§7). Fallback for any that convert
  poorly: draw with LVGL lines/arcs. Keep the star's hand-drawn character (do not substitute a geometric sparkle,
  §7).
- **Nav module (extend `ui.c`, or split `ui_nav.c`):** implement the screen stack + `nav_push(builder)` /
  `nav_back()` using `lv_scr_load_anim` MOVE_LEFT/RIGHT 240 ms (architecture decision above). A back arrow
  (`i-back`, violet) in the header pops; Home has none.
- **`build_header(parent, title_or_NULL)`:** 26 px top pad, ~64 px tall, serif 21 title (omitted on Home),
  right-aligned mono clock + battery, and the **1 px dashed `edge` rule** beneath inset 20 px each side (spec §4/§6;
  a styled bottom border or a thin dashed line object). Clock/battery show placeholders until P4.
- **List + rows (spec §4/§6):** a flex `lv_obj` list at 24–26 px inset; each row = `[icon] name … [tag?]
  [chevron]`, 16 px vertical padding, 16 px icon-name gap, **no dividers/boxes**. Row press = brighten name/icon
  (+ optional `pit-on` wash). Tag rules (§6): render a tag **only** when there's something to say — `ready`
  (steel), `running` (violet), or a count/short value; **never** an `idle` tag. Every row ≥ 44 px tall; no focus
  cursor (touch-only, §4).
- **Screens (per spec §11 screen map + mockup):** Home (WiFi · NFC · Bluetooth LE · USB Gadget · System);
  submenus for WiFi / NFC / Bluetooth LE / System with their module rows and the italic-serif section caption
  (`sub`, e.g. *802.11 · 2.4 GHz*); the USB Gadget action screen (built for real in P4); a WiFi → Scan action
  screen **shell** (header + `scanning…`/count line + 1 px sweep bar placeholder + empty AP list — no radio yet,
  M5). **Stub un-built modules present-but-disabled:** rows visible but non-navigating and dimmed
  (`lv_obj_add_state(row, LV_STATE_DISABLED)` + ash styling), so the map is legible before the capability lands.
- **Verify (on-device):** boot into Home; tap each category → submenu slides in from the right with fade; back
  arrow slides back from the left; rows show correct icons/captions/tags; disabled stubs don't navigate; the USB
  and System rows reach real content (System can show static build/version now). No shear (2-px rounder holds on
  the new layouts). Touch targets comfortable.
- **Risks:** `lv_scr_load_anim` with `auto_del=false` leaking screens if push/pop bookkeeping is wrong (keep a
  strict stack); dashed rule rendering (LVGL dashed borders are limited — may need a thin tiled line image or a
  row of dots as in the mockup's `dots`); icon recolor-on-press latency; row hit-area vs the M3 note that the
  demo button wanted a firm tap (loosen the indev press gate if rows feel stiff — RESUME open follow-up).

### P4 — Real bindings (RTC clock + battery %) + migrate M4 USB controls
**Goal / proves:** live header data, and the existing M4 composite-USB + DuckyScript path works **through the new
UI** (no regression).
- **RTC driver (`rtc.c/.h`, new):** PCF85063A **@ 0x51** on the shared I²C bus (`nocsif_i2c_bus()`, add device
  like power.c). Burst-read time regs **0x04–0x0A** (sec/min/hour/day/weekday/month/year, **BCD**), decode to a
  `struct tm`. Bit 7 of the seconds reg (0x04) is the **OS "oscillator-stopped/integrity-lost"** flag — if set,
  the time is unreliable (RTC lost backup); show `--:--` or seed a default and log it (a System → Time setter is
  out of scope for the shell — later milestone). VRTC (LDO1) can't be turned off, so once set it should hold.
  Expose `nocsif_rtc_get(struct tm*)` / `nocsif_rtc_time_valid()`.
- **Battery % (extend `power.c`):** add `nocsif_power_battery_percent(uint8_t*)`. Primary: AXP2101 **reg 0xA4**
  (`BAT_PERCENT_DATA`, 0–100) — **verify against XPowersLib** (`XPOWERS_AXP2101_BAT_PERCENT_DATA`), gated on
  battery-present (PMU status reg 0x00); the fuel-gauge/ADC may need enabling (reg 0x30/0x31 ADC-enable) at
  `nocsif_power_init()`. Fallback if 0xA4 reads 0/unpopulated: read VBAT ADC (reg 0x34 H / 0x35 L, 14-bit) and
  map through a LiPo voltage→% curve. Also expose charging state (reg 0x00/0x01) for a later charge glyph.
- **Header updater:** a **1 Hz `lv_timer`** on the LVGL task updates the visible header's clock + battery from
  cached values. The I²C reads (a few bytes each, sub-ms — lighter than the 33 Hz touch reads already done on the
  LVGL task in M3) may run directly in the timer; if ever measured as jittery, move them to a low-rate worker
  task that publishes into a cached struct and the timer only formats. Clock = mono 15 tabular; battery = mono 13
  (spec §3/§9).
- **Migrate the M4 controls into the USB Gadget action screen:** replace the three flat demo buttons in `ui.c`
  with the spec's USB action screen — the 4-row interface readout (`phy / cdc / msc / hid`) + a bracket-text
  `[ start gadget ]`⇄`[ stop gadget ]` control (mockup lines 242–255) wired to the **existing**
  `nocsif_usb_gadget_request_start()` / `nocsif_usb_gadget_state()`, plus a **Run Macro** control wired to the
  existing `nocsif_ducky_request_run(NULL)` / `nocsif_ducky_state()`. The callbacks only signal the workers
  (unchanged M4 `xTaskNotifyGive` pattern; never block the LVGL cb). The interface rows reflect
  `nocsif_usb_gadget_state()` (real enumeration handoff visualized in P5).
- **Running tags:** wire the Home WiFi/USB rows + submenu rows to real state where it exists now — USB `running`
  from `nocsif_usb_gadget_state()`; leave WiFi/NFC/BLE tags as stubs until their milestones. NFC "saved cards N"
  (live `/sd` count, §9) is deferred to M6.
- **Verify (on-device):** header clock advances against wall-clock and matches the RTC; battery % is plausible
  and tracks charging; **critical regression check** — through the new USB screen: tap start → the composite
  enumerates (CDC+MSC+HID with a card, CDC+HID without — the M4-P4 fallback), host drops `/sd/payload.txt`, tap
  Run Macro → it types into Notepad exactly as M4-P4 did, no stuck keys, no reboot. Everyday flash→read-COM7
  still works (gadget still deferred behind the tap).
- **Risks:** wrong PCF85063A register base or BCD mis-decode (validate against a known set time); AXP2101 gauge
  disabled → 0xA4 reads 0 (hence the ADC fallback + verify); doing I²C in the LVGL timer stalling the UI if a
  read ever blocks (bound with a short timeout, mirror power.c's 100 ms); **breaking the M4 signal path** while
  moving the buttons (keep the exact `request_start`/`request_run` calls; only the widget changes).

### P5 — Boot screen + motion helpers
**Goal / proves:** the boot reveal driven by **real** bring-up results, and the reusable functional-motion
primitives, with a global reduced-motion/power flag.
- **Boot screen (`ui_boot.c`, new):** a full-screen `NOCSIF_VOID` screen shown **first** (before Home), with the
  engraved violet star (P2 asset) + serif-30 `NOCSIF` wordmark (letter-spacing ~0.2em) + a `[ ok ]` bring-up log
  that reveals **line by line in the real init order** (spec §8 / HARDWARE.md): power rails (axp2101) → display
  (co5300) → touch (cst9217) → storage (`/sd` size or "no card") → usb (composite) → `ready`, then **fade to
  Home** (~550 ms). Drive each line from the **actual** init result: `main.c` already computes `display_ok`,
  `touch_ok`, SD init status, gadget init — pass these into the boot UI so each `[ ok ]`/`[ -- ]` reflects truth
  (e.g. "storage … no card" when SD init failed, matching the M4-P4 cardless path). Pace ~230 ms/line when the
  underlying step is instant; a terminal-style cursor blink (~1.05 s) on `ready` (boot only, §8).
- **Sequencing in `main.c`:** show the boot screen at the start of `nocsif_ui_init()` (or a `nocsif_ui_boot()`
  before it), replacing the M3 2-second RGB-band pause (keep the band self-test only behind a debug flag). Reveal
  log lines as each subsystem returns; on `ready`, `lv_scr_load_anim` fade to Home.
- **Motion helpers (`ui_motion.c` or inline):** factor the reusable timed reveals the spec §8 lists so M5+ screens
  drop into them: the **scan sweep** (a `violet` segment looping L→R on the 1 px bar, ~1.7 s) + **progressive AP
  reveal** (row fade/rise ~220 ms as the scan task reports — data source arrives M5, helper built now against the
  P3 scan shell), and the **USB enumeration handoff** (phy→released, cdc→com, msc→/sd, hid→ready lighting in
  sequence ~380 ms apart, **driven by real `nocsif_usb_gadget_state()`/`tud_mount` transitions**, reverse on stop
  — this one has its real data source *now*, so wire it fully into the P4 USB screen).
- **Reduced-motion / power flag (spec §8):** a single global that collapses all reveals to their final state
  instantly (boot log all-shown then fade; sweep off; handoff jumps to final). Default on-device: motion **on**;
  flag flips it for power.
- **Verify (on-device):** cold boot shows the star + NOCSIF + the log revealing in true bring-up order with
  honest per-line results, then fades to Home; pull the SD and reboot → the storage line reads "no card" and USB
  still reaches `ready` (CDC+HID); the USB screen's handoff animation matches the *actual* enumeration you see on
  the host; setting the reduced-motion flag collapses everything to final state.
- **Risks:** boot screen racing the async init (reveal a line only after its result is known, not on a fixed
  timer, where the result exists); the fade-to-Home firing before Home is built (build Home first, then animate);
  the enumeration-handoff animation drifting from reality if it's timer-driven instead of event-driven (bind it
  to `nocsif_usb_gadget_state()` transitions); leftover M3 band-test pause slowing boot (remove/guard it).

## Key gotchas (carry into coding)
- **Per-widget serif selection is mandatory** — titles default to Montserrat otherwise (spec §3). Every serif
  title/caption/wordmark sets `lv_obj_set_style_text_font` explicitly.
- **Keep the M3 flush invariants verbatim:** `buff_dma=false`, `color_format=LV_COLOR_FORMAT_RGB888`, the 2-px
  `ui_rounder_cb`, `CONFIG_LV_COLOR_DEPTH_24=y` (=y, not =24). New layouts must not reintroduce odd-column
  shear; the rounder already covers it but verify on the list rows.
- **Colors normal, not byte-swapped** — panel BGR handling is in the flush config (M3). Use `lv_color_hex()`.
- **Background renders ONCE** into `lv_layer_bottom()`; never invalidate it. Screens are transparent so it shows
  through. No idle/ambient animation anywhere (spec §8, power).
- **LVGL single-threaded behind esp_lvgl_port:** UI callbacks only `xTaskNotifyGive` workers (clone the M4
  pattern); any widget mutation off the LVGL task holds `lvgl_port_lock()`. RTC/battery reads are light enough
  for the 1 Hz LVGL timer, but bound them with a short I²C timeout.
- **Do not regress M4:** the USB start/stop and Run Macro controls must call the exact existing
  `nocsif_usb_gadget_request_start()` / `nocsif_ducky_request_run()` — only the widgets change, not the worker
  signalling or the CDC+MSC+HID / CDC+HID-fallback behavior.
- **Boot log must be honest** — each line reflects the real init result (`display_ok`, `touch_ok`, SD status),
  not a canned success; "no card" is a valid, expected line (M4-P4 cardless path).
- **Build from PowerShell with `-j 2`** (default parallelism OOMs the Windows paging file — RESUME); after any
  sdkconfig change verify the symbol landed in the generated `sdkconfig`.

## Open decisions (defaults chosen; none block P1)
- **Serif face:** Recia vs Boska — **decide in P1** by rendering both at 21 px on-panel (spec §12).
- **Screen architecture:** default **separate `lv_screen`s + `lv_scr_load_anim`** (fallback: single-screen
  container views) — confirmed/rejected by the P2 compositing test.
- **Background implementation:** default **`lv_canvas` drawn once in PSRAM** (fallback: pre-rendered flash
  image) — decided in P2.
- **RTC time when integrity flag is set:** default **show `--:--` + log**; a Time-setter UI is a later
  milestone (spec §11 System is "anytime/M11 polish").
- **CRT scanline overlay** (mockup texture): default **off** (power, spec §12) — revisit only if wanted.
- **Header clock: per-screen (slides with the header, matches mockup) vs a persistent non-sliding status bar.**
  Default **per-screen** via `build_header()` (matches the mockup); the updater targets the visible header.
